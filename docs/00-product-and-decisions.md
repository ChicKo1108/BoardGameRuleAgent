# 产品范围与技术决策

## 目标

建设真实可上线的商业项目，后续作为面试作品。核心投入是知识库与 RAG 的正确性、可追溯性和可评测性。
首版范围较小不意味着降低工程标准；技术复杂度需有实验依据。

## 已确认需求

- 问答式桌游规则助手，优先帮助会玩但忘记细节的玩家，其次解决规则争议。
- 首款游戏：花砖物语 Azul 基础版。具体玩法面和中文规则书版本待资料核验。
- 默认简短回答、附来源、可展开依据；只支持文字和连续追问。
- 有歧义时：指出歧义 → 按最可能解释回答并注明条件 → 确认是否回答了用户的问题。
- 允许规则推导，但要区分原文和推导，依据不足不得强行裁定。
- 仅使用管理员维护并已发布的资料；在线 Agent 不联网。
- 公共网站，首发面向中国大陆；免费限额公测，游客少量试用、登录后更多额度。
- 独立网站采用微信扫码登录；资质和审核暂缓讨论，不阻碍核心研发。
- 保留历史对话；匿名用户原浏览器访问，登录后历史策略在账号模块落实。
- 模型服务统一由服务端配置；服务商、模型、费用额度待评测。
- 单管理员后台维护；暂不做多人审核、用户投稿、支付、用户反馈按钮。

## 已确认技术

Next.js 前后端；Pi Agent；PostgreSQL + pgvector；TypeORM；Swagger/OpenAPI；Sentry。
自建知识管理与检索业务，复用解析、数据库及模型组件。

## 设计提案与待验证项

- 模块化单体 + 独立 Node Worker。
- pg-boss 为任务队列候选；Docling 为解析器候选。
- 首版不以 RAGFlow/LlamaIndex 为核心依赖。需要时通过适配器引入。
- 关键词与向量混合召回，融合、重排、关联补全分别通过实验验证。
- Embedding、Reranker、切分长度、召回数量和相似度阈值均未定案。

## 已被替代的早期决定

“只给朋友试用、不注册”已调整为公开免费限额公测和游客+登录体系。
Drizzle 已改为 TypeORM；独立 OpenTelemetry 后端不属于首版选型，监控采用 Sentry。
全文输入仅作对照实验，不作为绕过知识库建设的理由。

## 代码交付约定（2026-11-05）

首次初始化推送至空仓库 main。后续代码修改按功能分支提交，完成相关验证后自动推送并创建 PR；同功能继续更新原 PR。不自动合并、不直接向 main 推送功能修改。仓库根 AGENTS.md 记录执行规则。
